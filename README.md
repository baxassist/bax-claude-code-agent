# Bax Claude Code Agent

Движок, который даёт управлять Claude Code с телефона. Запускается на вашем компьютере,
соединяется с сервером Бакса — личного ИИ-помощника — по websocket, и дальше задачи
ставятся из мобильного приложения: вы пишете, что сделать, агент выполняет это в указанной
папке проекта и возвращает ответ.

**Словарь.** *Движок* — эта программа вместе с Claude Code. *Агент* — то, что вы видите
в приложении: проект, в котором движок работает; имя ему даёте вы, движок его не знает.
Один компьютер — один движок и сколько угодно агентов, по одному на проект.

Зачем: разрабатывать, не сидя за компьютером. Особенно когда нужен macOS — например, для
мобильной разработки: задача ставится с телефона, сборка и правки идут на маке.

**Статус: рабочая версия.** Агент подключается к Баксу, объявляет проекты, принимает задачи
(в том числе с картинками), отдаёт ответ на лету, спрашивает разрешения карточкой в телефоне,
умеет «Стоп» и остановку фоновых задач, отдаёт файлы, дерево, git и свой лог, показывает
ресурсы машины и переключает модель, усилие, режим разрешений и сессию. Claude Code водится
через официальный **Claude Agent SDK** (22.09): CLI идёт внутри пакета SDK и обновляется
вместе с ним, а разрешения приходят колбэком прямо в процесс движка.

**Не хотите движок на весь компьютер?** Есть
[Claude Code Lite](https://github.com/baxassist/bax-claude-code-lite-agent) — плагин внутри уже
открытой вами сессии Claude Code: задачи с телефона приходят в неё, ответы уходят обратно.
Умеет меньше (остановка, модель и сессии — в терминале), зато ничего не запускает сам.

## Как это работает

1. В приложении Бакса заводите агента: имя, цвет. Он сразу даёт **строку регистрации**
   `<id агента>:<id ключа>:<секрет>`.
2. На компьютере ставите движок и регистрируете этим агентом каталог проекта:

   ```bash
   bax-agent add "<строка>" --path ~/projects/api
   bax-agent run
   ```

3. В приложении агент загорается зелёным. Открываете его — и работаете: задачи, ответы,
   вопросы с кнопками, «Стоп», ресурсы машины, запрос файлов.

Каталог задаётся только на компьютере: приложение добавить его не может, так ошибка
или чужая команда не откроют доступ к лишнему. Агентов у одной установки может быть
сколько угодно — по одному на проект, у каждого свой ключ и своё соединение.

## Что уже проверено на практике

Claude Agent SDK 0.2.157 (внутри Claude Code CLI 2.1.277), авторизация по подписке
(без ключа API):

- **Долгоживущая сессия** — один `ClaudeSDKClient` на агента: реплики досылаются в работающий
  процесс, сессию не нужно каждый раз прогревать.
- **Вопросы и разрешения** — колбэк `can_use_tool` внутри процесса движка: когда Claude Code
  хочет сделать что-то, требующее разрешения, движок показывает карточку в приложении и ждёт
  человека. Смысловые вопросы с вариантами — свой MCP-инструмент `ask_user`, тоже внутри
  процесса: отдельный сервер и юникс-сокет больше не нужны.
- **Остановка** — `client.interrupt()`: текущий ход прерывается, процесс и сессия остаются живы.

## Что нужно

- Python 3.11+
- Активная подписка Claude (вход как в Claude Code: `claude` → «Sign in»).
  Отдельно ставить Claude Code не обязательно — CLI идёт внутри пакета SDK, поэтому
  установка тянет около 90 МБ. Свой CLI задаётся `claude_path` в `[engine]`.
- Аккаунт в Баксе (мобильное приложение)

## Безопасность

Агент выполняет код на вашей машине, поэтому:

- каталоги проектов перечисляются только в конфиге на самом компьютере;
- режим разрешений выбирается на поток: ничего не менять, править файлы, спрашивать всё;
- всё, что делает агент, пишется в его лог;
- ключ агента можно отозвать из приложения;
- запускать агента под отдельным пользователем ОС, не под root;
- агент всегда принадлежит одному человеку: совместного доступа нет и не будет — кому нужен
  такой же, поднимает свой.

## Установка и запуск

```bash
git clone https://github.com/baxassist/bax-claude-code-agent.git
cd bax-claude-code-agent
uv sync                                  # или: pip install -e .
cp config.example.toml config.toml       # адрес сервера Бакса в нём уже вписан
bax-agent add "<строка из приложения>" --path ~/projects/api
bax-agent run
```

Команды: `add` — зарегистрировать агента, `list` — что зарегистрировано, `remove <id>` —
перестать обслуживать его здесь (в приложении агент останется), `run` — работать.

Рядом с конфигом движок держит `agents.json` (id агентов, каталоги и ключи, права 600),
`.install` (id этой установки) и `agent.log` — в git они не попадают (`.gitignore`). Строка регистрации работает **только на одной
машине**: первая установка, подключившаяся ею, закрепляет ключ за собой — вторая получит
отказ. Нужен переезд — перевыпустите строку в приложении.

Потеряли `agents.json` — перевыпустите строки в приложении: имена и настройки агентов
сохранятся, они на сервере, а переписка лежит в файлах сессий Claude Code на этой машине.

## Что внутри

| Файл | За что отвечает |
| --- | --- |
| `bax_agent/config.py` | конфиг движка, регистрации агентов, id установки |
| `bax_agent/connection.py` | websocket на агента: рукопожатие его ключом, переподключение с нарастающей паузой |
| `bax_agent/claude.py` | долгоживущая сессия Claude Code поверх Claude Agent SDK |
| `bax_agent/agents.py` | агент = проект: кадры приложения ↔ события Claude Code |
| `bax_agent/engine.py` | движок целиком: одно соединение и по агенту на проект |
| `bax_agent/history.py` | история из файлов сессий Claude Code — своей копии агент не держит |
| `bax_agent/rules.py` | «больше не спрашивать» точечным правилом, а не на весь инструмент |
| `bax_agent/commands.py` | файл, дерево, git, лог — строго внутри каталога проекта |
| `bax_agent/resources.py` | загрузка машины, ветка, версия CLI, списки моделей и усилий |
| `bax_agent/events.py` | свои события агента: остановка, перезапуск, смена модели |

Тесты (`uv run pytest`) поднимают поддельный сервер Бакса и подставной клиент SDK, так что путь
кадра проверяется целиком, без сети и без расхода подписки.

## Документация

Описание протокола обмена (чтобы можно было написать своего агента) и разбор частых
вопросов появятся здесь к первому релизу.

## Режимы разрешений

Слова те же, что у самого Claude Code (`--permission-mode`):

| Режим | Что делает |
| --- | --- |
| `manual` | спрашивает разрешение на каждое действие — карточка приходит в телефон |
| `acceptEdits` | правит файлы в проекте молча, про команды спрашивает |
| `plan` | только смотрит и предлагает план, ничего не меняет |
| `dontAsk` | всё, что требует разрешения, запрещается сразу |
| `auto` | решает встроенный классификатор — **вопросы в приложение не приходят** |
| `bypassPermissions` | разрешает всё подряд; только если понимаете, чем рискуете |

Режим задаётся на проект в конфиге и меняется из приложения. Дополнительно у проекта есть
`restricted = true`: Claude Code запускается без инструментов, выполняющих команды, а файловые
операции запираются в каталоге проекта.

## Что агент не делает

- не даёт доступ к каталогам вне конфига — приложение новый каталог добавить не может;
- не хранит переписку у себя: история читается из файлов сессий Claude Code;
- не делится агентом с другими людьми — совместного доступа нет и не будет;
- не отправляет задачу в работу без вас: надиктованный текст только подставляется в поле.
